# Expected outcomes of the tenant harness other than `pass` (README.md).
#
#   mode      persona  suite      connector          check            status  reason
#
# `*` matches anything; `-` is "no connector" (every suite but hibernate).
# The last matching line wins, so put the general lines first. A check
# passes the matrix only when its status equals the expected one, so an
# unexpected pass is reported too and this file stays accurate.

# MySQL Connector/J 9.7's DatabaseMetaData.getSQLKeywords() reads
# information_schema.KEYWORDS WHERE RESERVED = 1, which MariaDB doesn't have,
# so against MariaDB directly Hibernate can't resolve a dialect and validation
# fails before it looks at a table. The rest of the check runs after a restart
# without validation and must pass. Through the gateway the translator answers
# KEYWORDS with MySQL 8.4's list, and the check passes.
baseline  mysql    hibernate  hibernate          schema_validate  fail    MySQL Connector/J reads information_schema.KEYWORDS.RESERVED, which MariaDB lacks

# Baseline: direct MariaDB has no physical names to leak, so the leak checks
# report n/a (the Rust leak suite still asserts that its detector catches the
# probe names MariaDB echoes in its errors, which proves the byte scan).
baseline  *        dump       -                  dump_leaks       n/a     no physical names exist in baseline
baseline  *        isolation  -                  isolation_leaks  n/a     no physical names exist in baseline
baseline  *        leaks      -                  leaks            n/a     no physical names exist in baseline
# ... and SprigDB's settings statements don't exist in MariaDB.
baseline  *        settings   -                  object_scope     n/a     MariaDB has no SPRIG SET (it answers 1064)
baseline  *        settings   -                  out_of_bounds    n/a     MariaDB has no SPRIG SET (it answers 1064)
baseline  *        settings   -                  scope_bounds     n/a     MariaDB has no SPRIG SET (it answers 1064)
baseline  *        settings   -                  object_only      n/a     MariaDB has no SPRIG SET (it answers 1064)
# mysqldump 8.4's --all-databases dumps the `mysql` database first: it holds
# back every database SHOW DATABASES lists until it reaches `mysql`, and if
# `mysql` never comes it writes nothing and still says "Dump completed".
# Neither a tenant through the gateway nor a plain MariaDB user sees
# `mysql`, and MySQL 8.4 behaves the same for a user who can't see it.
# dump_listed passes with the workaround, --databases with SHOW DATABASES's
# list.
*         mysql    dump       -                  dump_all         fail    mysqldump 8.4 --all-databases dumps nothing unless SHOW DATABASES lists mysql
